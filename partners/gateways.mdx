Gateways de pagamento sao o coracao do ecossistema de transacoes digitais no Brasil. Ao se tornar um parceiro gateway da Sync Apps, sua plataforma oferece PIX nativo aos comerciantes sem precisar construir toda a infraestrutura bancaria do zero. A Sync Apps cuida da geracao de cobrancas, emissao de QR Codes, confirmacao de pagamentos e reconciliacao, enquanto seu gateway mantem a relacao com o comerciante. O resultado e uma experiencia de checkout mais rapida, taxas menores e confiabilidade tecnica comprovada por milhares de transacoes processadas diariamente.

## Quem se Enquadra como Gateway

Se sua empresa se encaixa em algum dos perfis abaixo, a categoria Gateway e a ideal para sua inscricao:

- **Adquirentes e sub-adquirentes**: empresas que capturam transacoes para comerciantes e precisam oferecer PIX como metodo de pagamento
- **Gateways white-label**: plataformas que vendem infraestrutura de pagamento para outros negocios reembalarem sob sua marca
- **Processadores de pagamento**: servicos que roteiam transacoes entre comerciantes, adquirentes e bancos
- **Fintechs de pagamento**: empresas que oferecem conta digital com funcionalidade de recebimento via PIX
- **Plataformas de split de pagamentos**: servicos que dividem o valor de uma transacao entre multiplos recebedores

## Requisitos Tecnicos

Para garantir uma integracao segura e escalavel, parceiros gateway devem atender aos seguintes requisitos tecnicos:

- **Infraestrutura HTTPS**: todos os endpoints de webhook devem usar TLS 1.2 ou superior com certificado valido
- **Idempotencia**: implemente controle de idempotencia nas chamadas a API para evitar duplicacao de cobrancas em caso de timeout ou retry
- **Validacao de assinatura**: verifique a assinatura digital (signature) dos webhooks enviados pela Sync Apps para confirmar autenticidade
- **Resposta rapida**: endpoints de webhook devem responder em ate 5 segundos com status HTTP 200. Respostas lentas ou erros 5xx acionam retries automaticos
- **Retry handling**: esteja preparado para receber o mesmo webhook multiplas vezes. Use o campo `event_id` para deduplicar no seu sistema
- **Sandbox primeiro**: todas as integracoes devem ser validadas no ambiente de testes antes de solicitar migracao para producao

## Como Funciona a Integracao

O fluxo de integracao para gateways segue um padrao claro e bem documentado:

<Steps>
  <Step title="Criar cobranca via API">
    Seu gateway chama o endpoint `POST /v1/payments` da Sync Apps passando o valor, descricao, expiracao e dados do comerciante. A API retorna um objeto de cobranca com o QR Code e o copia-e-cola.
  </Step>
  <Step title="Exibir ao pagador">
    Seu frontend ou checkout exibe o QR Code ou o codigo PIX para o cliente final. O pagamento e feito diretamente no app do banco do pagador.
  </Step>
  <Step title="Receber webhook de confirmacao">
    Assim que o pagamento e confirmado pela rede bancaria, a Sync Apps envia um webhook para o endpoint configurado no seu gateway com todos os detalhes da transacao.
  </Step>
  <Step title="Liberar e notificar o comerciante">
    Seu gateway processa o webhook, atualiza o status da transacao no seu sistema e notifica o comerciante de que o pagamento foi recebido com sucesso.
  </Step>
</Steps>

## Exemplo de Codigo

Veja como criar uma cobranca PIX a partir do seu gateway usando diferentes linguagens e ferramentas:

<CodeGroup>

```bash curl
# Criar uma cobranca PIX de R$ 50,00
curl -X POST https://api.syncpay.com.br/v1/payments \
  -H "Content-Type: application/json" \
  -H "X-API-Key: sua_api_key" \
  -d '{
    "amount": 5000,
    "currency": "BRL",
    "description": "Pedido #12345",
    "expires_in": 3600,
    "merchant_id": "merchant_abc123",
    "callback_url": "https://seugateway.com.br/webhooks/syncpay"
  }'
```

```javascript JavaScript
const response = await fetch('https://api.syncpay.com.br/v1/payments', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'X-API-Key': 'sua_api_key'
  },
  body: JSON.stringify({
    amount: 5000,
    currency: 'BRL',
    description: 'Pedido #12345',
    expires_in: 3600,
    merchant_id: 'merchant_abc123',
    callback_url: 'https://seugateway.com.br/webhooks/syncpay'
  })
});

const payment = await response.json();
console.log('QR Code:', payment.qr_code);
console.log('Copia e Cola:', payment.pix_copy_paste);
```

```python Python
import requests

payment = requests.post(
    'https://api.syncpay.com.br/v1/payments',
    headers={
        'Content-Type': 'application/json',
        'X-API-Key': 'sua_api_key'
    },
    json={
        'amount': 5000,
        'currency': 'BRL',
        'description': 'Pedido #12345',
        'expires_in': 3600,
        'merchant_id': 'merchant_abc123',
        'callback_url': 'https://seugateway.com.br/webhooks/syncpay'
    }
).json()

print('QR Code:', payment['qr_code'])
print('Copia e Cola:', payment['pix_copy_paste'])
```

</CodeGroup>

## Resposta da API

A resposta da API contem todos os dados necessarios para apresentar a cobranca ao pagador e rastrear a transacao:

```json
{
  "id": "pay_abc123def456",
  "status": "pending",
  "amount": 5000,
  "currency": "BRL",
  "description": "Pedido #12345",
  "qr_code": "data:image/png;base64,iVBORw0KGgo...",
  "pix_copy_paste": "00020126580014BR.GOV.BCB.PIX0136...",
  "expires_at": "2024-01-15T14:30:00Z",
  "created_at": "2024-01-15T13:30:00Z",
  "callback_url": "https://seugateway.com.br/webhooks/syncpay",
  "merchant_id": "merchant_abc123"
}
```

**Campos importantes:**

<ParamField path="id" type="string">
  Identificador unico da cobranca na Sync Apps. Use para consultas e reconciliacao.
</ParamField>

<ParamField path="status" type="string">
  Estado atual: `pending`, `paid`, `expired` ou `cancelled`.
</ParamField>

<ParamField path="qr_code" type="string">
  Imagem do QR Code em formato base64. Pode ser renderizada diretamente em um elemento `<img>`.
</ParamField>

<ParamField path="pix_copy_paste" type="string">
  String do PIX copia e cola para usuarios que preferem pagar manualmente no app do banco.
</ParamField>

<ParamField path="expires_at" type="string">
  Data e hora de expiracao da cobranca no formato ISO 8601. Apos esse horario, o status muda para `expired`.
</ParamField>

## Webhook de Confirmacao

Quando o pagador confirma a transacao no app do banco, a Sync Apps envia um webhook para o `callback_url` configurado:

```json
{
  "event": "payment.confirmed",
  "event_id": "evt_xyz789abc",
  "timestamp": "2024-01-15T13:35:22Z",
  "data": {
    "id": "pay_abc123def456",
    "status": "paid",
    "amount": 5000,
    "currency": "BRL",
    "paid_at": "2024-01-15T13:35:18Z",
    "payer_info": {
      "name": "Joao Silva",
      "tax_id": "***.***.***-00"
    }
  }
}
```

<ResponseField name="event" type="string">
  Tipo do evento. Para pagamentos confirmados, sempre `payment.confirmed`.
</ResponseField>

<ResponseField name="event_id" type="string">
  Identificador unico do evento. Use para deduplicar webhooks recebidos mais de uma vez.
</ResponseField>

<ResponseField name="data.paid_at" type="string">
  Data e hora exata em que o pagamento foi confirmado pela rede bancaria.
</ResponseField>
