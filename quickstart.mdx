Neste guia, você vai aprender a criar sua conta na Sync Apps, gerar uma API Key e processar seu primeiro pagamento PIX em menos de 5 minutos. Ao final deste tutorial, você terá criado uma cobrança PIX, recebido os dados do QR Code para pagamento e configurado um webhook para receber notificações automáticas quando o pagamento for confirmado. Tudo isso utilizando nossa API REST moderna e documentada. Vamos começar!

<Steps>
  <Step title="Criar sua conta">
    Acesse o [Dashboard da Sync Apps](https://syncpay.com.br/dashboard) e clique em "Criar Conta". Você precisará informar seu e-mail corporativo, criar uma senha segura e confirmar seu número de telefone via SMS. O processo de validação é automático e leva menos de 2 minutos. Após a confirmação, você terá acesso ao painel completo da plataforma.
  </Step>
  <Step title="Gerar sua API Key">
    Dentro do Dashboard, navegue até **Configurações \> API Keys** e clique em "Nova API Key". Dê um nome descritivo para facilitar a identificação futura, como "Produção" ou "Testes". A chave será exibida apenas uma vez, então copie-a imediatamente e armazene em um local seguro. Nunca compartilhe esta chave publicamente.
  </Step>
  <Step title="Sua primeira requisição">
    Agora vamos criar seu primeiro pagamento PIX. Utilize o endpoint `POST /v1/payments` com os dados da cobrança. Abaixo estão exemplos em três linguagens diferentes:

    <CodeGroup>

    ```bash
    curl -X POST https://api.syncpay.com.br/v1/payments \
      -H "Content-Type: application/json" \
      -H "X-API-Key: sua_api_key" \
      -d '{
        "amount": 150.00,
        "description": "Pagamento de teste - Sync Apps",
        "webhook_url": "https://seusite.com/webhook/syncpay"
      }'
    ```

    ```javascript
    const response = await fetch('https://api.syncpay.com.br/v1/payments', {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json',
        'X-API-Key': 'sua_api_key'
      },
      body: JSON.stringify({
        amount: 150.00,
        description: 'Pagamento de teste - Sync Apps',
        webhook_url: 'https://seusite.com/webhook/syncpay'
      })
    });
    
    const data = await response.json();
    console.log(data);
    ```

    ```python
    import requests
    
    response = requests.post(
        'https://api.syncpay.com.br/v1/payments',
        headers={
            'Content-Type': 'application/json',
            'X-API-Key': 'sua_api_key'
        },
        json={
            'amount': 150.00,
            'description': 'Pagamento de teste - Sync Apps',
            'webhook_url': 'https://seusite.com/webhook/syncpay'
        }
    )
    
    data = response.json()
    print(data)
    ```

    </CodeGroup>
  </Step>
  <Step title="Entendendo a resposta">
    A API retornará um JSON completo com todos os dados da cobrança criada. Veja o exemplo de resposta e a explicação de cada campo na próxima seção.
  </Step>
  <Step title="Configurar Webhook">
    O webhook é a forma mais eficiente de receber notificações de pagamento. Quando o pagador confirmar a transação no aplicativo do banco, nossa plataforma enviará uma requisição POST para a URL que você informou no campo `webhook_url`. Seu endpoint deve retornar um status HTTP 200 para confirmar o recebimento. Caso contrário, tentaremos novamente automaticamente.
  </Step>
</Steps>

## Exemplo de Resposta

Quando você cria um pagamento PIX, a API retorna um objeto JSON completo com todas as informações necessárias para apresentar ao pagador:

```json
{
  "id": "pay_1234567890abcdef",
  "status": "pending",
  "amount": 150.00,
  "currency": "BRL",
  "description": "Pagamento de teste - Sync Apps",
  "qr_code": "data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAA...",
  "qr_code_text": "00020101021226830014br.gov.bcb.pix2561...",
  "created_at": "2024-01-15T14:30:00Z",
  "expires_at": "2024-01-15T15:30:00Z",
  "webhook_url": "https://seusite.com/webhook/syncpay"
}
```

**Campos da resposta:**

- `id` — Identificador único da transação na Sync Apps. Utilize este ID para consultar o status futuramente.
- `status` — Status atual do pagamento. Valores possíveis: `pending`, `paid`, `expired`, `cancelled`.
- `amount` — Valor da cobrança em reais (R\$).
- `currency` — Moeda da transação. Sempre `BRL` para pagamentos PIX no Brasil.
- `description` — Descrição que você enviou na criação da cobrança.
- `qr_code` — Imagem do QR Code em formato Base64. Você pode renderizá-la diretamente em uma tag `<img>` no HTML.
- `qr_code_text` — Texto do QR Code no formato "Copia e Cola". O pagador pode copiar este texto e colar diretamente no aplicativo do banco.
- `created_at` — Data e hora da criação da cobrança no formato ISO 8601.
- `expires_at` — Data e hora de expiração da cobrança. Após este horário, o QR Code não poderá mais ser pago.
- `webhook_url` — URL configurada para receber notificações de mudança de status.

<Note>
  **QR Code e Copia e Cola:** A resposta contém duas formas de apresentar o QR Code ao pagador. O campo `qr_code` é uma imagem PNG codificada em Base64, ideal para exibição visual. O campo `qr_code_text` é o texto no formato "Copia e Cola" do PIX, que permite ao usuário copiar e colar diretamente no app do banco. Recomendamos oferecer ambas as opções em sua interface.
</Note>

## Evento de Webhook

Quando o pagamento for confirmado pelo pagador, nossa plataforma enviará um POST para sua `webhook_url` com o seguinte payload:

```json
{
  "event": "payment.paid",
  "data": {
    "id": "pay_1234567890abcdef",
    "status": "paid",
    "amount": 150.00,
    "currency": "BRL",
    "paid_at": "2024-01-15T14:35:22Z",
    "payer_info": {
      "name": "João Silva",
      "tax_id": "***.***.***-**"
    }
  }
}
```

O campo `event` identifica o tipo de notificação. Neste caso, `payment.paid` indica que o pagamento foi confirmado. O objeto `data` contém os detalhes atualizados da transação, incluindo o horário exato do pagamento (`paid_at`) e informações resumidas do pagador.

<Warning>
  **Nunca exponha sua API Key no frontend:** Sua API Key deve ser utilizada apenas no backend da sua aplicação. Nunca a inclua em código JavaScript que roda no navegador do cliente, em repositórios públicos ou em documentação compartilhada. Se você precisa criar cobranças a partir do frontend, implemente um endpoint no seu backend que chame a API da Sync Apps.
</Warning>
